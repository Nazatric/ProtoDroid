# Rejected changes and non-actions

This record includes both standing non-actions and experimentally rejected candidates.

## Standing non-actions

- Fake FPS values, generated-frame inflation, hidden resolution/texture/effect reductions, frame skipping, and unconditional movie skipping.
- Presenting host or ARM64-runner microbenchmarks as physical-device FPS, GPU time, latency, or thermal results.
- Spoofing Vulkan features/extensions or equating extension presence with feature support.
- Wholesale FEX, SDL3, renderer, DXVK, or engine replacement without a specific measured need and compatibility plan.
- Copying external code before license/provenance review.
- Treating `iss_android` preparation or another project's README as proof of Android performance.
- Sacrificing dynamic shadows, Bink A/V, compatible mods/saves, Classic controls, FIFO/Reset safety, or independent AA policy for performance.
- Building an APK for every small edit or releasing/merging 0.16 without explicit final authorization.

## Rejected evidence combinations

- `TestingFiles` `b2ca160b…` `proto-native.log` plus `journal.log`: rejected as a single run because their embedded sources are `54ef821e…` and `e34ebb06…`. Separate parsing is retained for historical inspection only.
- Root `51e51ea…` logs as released-0.15 results: rejected because the source revision does not match the release.

## Phase 2 audit-level non-actions

These are source/applicability decisions, not controlled performance experiments:

- **Duplicate dispatch rewrite:** rejected. Bloodborne's `0x9E3779B1` open-addressed lookup is already structurally present in both ProtoDroid recompilation dispatch paths.
- **Extra Mali compiler workers or a second warm-up architecture:** rejected without new evidence. ProtoDroid already caps Mali workers at two; affected Mali driver pipeline calls remain serialized for correctness. Direct DXVK 2.5.3 inspection also confirms existing lowest-priority pipeline workers, warm-cache compilation, and a separate cache writer.
- **Black-mobiu “async” shader or cache-format import:** rejected because the pinned glslang path is synchronous on a cache miss. Fresh direct component stress confirms global serialization, but does not prove game-workload duplication through the caller's module memoization/render worker. Its SPIR-V loader/format and D3D8 renderer are not DXVK drop-ins; DXVK's SHA-1-protected pipeline-state entries are a different layer.
- **PrototypeRecomp “async host I/O” or GDFX locking import:** rejected because host reads/writes finish synchronously before guest `PENDING`/APC/event completion. Fresh production-code observation confirms `io_mutex_` serializes `pread`; ProtoDroid's per-fd read path has no equivalent global lock. GDFX region lookup is not a reason to replace the existing RCF index, and its full-length zero-fill on missing backing data must not be used to hide corruption.
- **Generic batching/state-tracking/staging-reuse rewrite:** rejected as a duplicate proposal. Direct DXVK inspection confirms recycled CS chunks, a CS thread, change/dirty-state handling, linear staging suballocation, and an in-flight staging threshold. Only a measured residual cost could justify a narrow change.
- **GoW III/ISS large staging defaults:** rejected. A 128 MiB prewarm and 512 MiB retention policy has no ProtoDroid memory/stall justification and is not equivalent to DXVK's existing staging-in-flight metric.
- **Speculative draw-pipeline import:** rejected as a direct patch. Its PC evidence is not Android evidence, the GoW III Android configuration disables preparation workers by default, and D3D9/DXVK has a different architecture.
- **Bloodborne unified-memory/KGSL/AOT/affinity import:** rejected. UMA showed memory savings without automatic FPS improvement and includes serious coherence/reset risks; unmodified focused UBSan also stops on a zero-length null-`memmove` in `runtime_memory.c::vma_erase`, and only a preserved test-only zero-byte-guard copy completes both UBSan configurations. UMA TSan also remains negative/unresolved: the original fixture has a stop-flag race, and a test-only atomic-stop rerun reaches a writer/`MAP_FIXED` model report rather than a clean pass. No external source fix or ProtoDroid patch is adopted. AOT was approximately tied with FEX at a GPU-bound save; its variants test also retains a two-`HookRec` LSan failure (with only UBSan-only passing), so hook-record lifetime/replacement growth would need resolution rather than concealment. Fixed affinity is not justified without ProtoDroid thread evidence. This does not reject or remove ProtoDroid's unrelated upstream DXVK memory-type-selection compatibility backport in `dxvk-unified-memory.patch`.
- **GoW III readback page-watcher/queue import:** rejected as incompatible with D3D9/DXVK resource lifetime. Existing DXVK/Android Present diagnostics already expose aggregate GPU/CS sync timing; only a profile-driven need for finer attribution remains open.
- **Generated/upscaled frames as performance evidence:** rejected. Bloodborne's 29.2 game-FPS result is not 60 real FPS, and GoW III PC/upscaler scenes are not ProtoDroid phone results.
- **ISS as independent confirmation:** rejected. Its Android port is preparation-only, and its async/draw/staging implementations share substantial lineage with the GoW III fork.

## Phase 3 rejected evidence uses

- **Optimized RCF gprof call graphs:** rejected for attribution because impossible/unreachable arcs persisted in PIE and non-PIE diagnostics. Limited reachable flat PC samples remain only with startup/teardown/harness exclusions.
- **Historical heavy pipeline trace as clean timing:** rejected because shader dumps and `fsync` ran inside the compile lock for all 171 graphics calls. Future timing must separate `pipeline_trace=0` from structural tracing.
- **Original Bink decode cohort:** rejected after proving the evidence-only guest stack overlapped input at offset 3,145,712. Its old digest/timings and resulting frame-73 failure are not production evidence; corrected dedicated-stack cohorts are retained separately.
- **Cross-harness or instruction-count rankings:** rejected. DXT, mixer, RCF, Bink, and historical windows have no common frame denominator, and AArch64 instruction counts are not cycle/device shares.
- **Ascending-only destination-slot interpretation:** rejected as confounded by order/frequency. The retained result uses three ascending plus three descending repetitions and paired ratios, still without claiming cache causation or ARM64 transfer.

## Experimentally rejected candidates

- **Phase 4 split key/function arrays:** provisional integration was reversed and the original runtime restored. Independent shuffled localized workloads reproduced regressions: split/original paired medians 1.035959 at 16 targets, 1.034367 at 256, and 1.157686 at 16,384; mixed/small-dispatch results did not establish a beneficial real target mix. Lookup16 was slower in 12/12 pairs in both protocols, while lookup4096 improved in 11/12 and 10/12, confirming a workload tradeoff rather than a universal direction. Standard cold/miss gains remain valid synthetic evidence but are insufficient for adoption.
- **Phase 4 parallel indexed 32-bit hash slots:** rejected for adoption despite lower cold/memory and some warm gains. The initial zero-target association bug was corrected and preserved; the valid candidate regressed repeated-target lookup (paired candidate/original median 1.052112) and had variable other results. No split or indexed layout remains in production.
- **Phase 4 flat direct table:** rejected analytically. Real entries lack uniform alignment and span 14,199,324 bytes; byte-granular pointers alone would require 113,594,592 bytes, versus 3,145,728 bytes for the split hash.
- **Phase 4 17-bit table:** rejected from exact probe behavior (12.873683 mean successful and 446.796510 mean synthetic-miss probes) plus a separately labeled bounded smoke. Its near-full load factor is not a safe performance/memory trade.
- **Phase 4 19-bit table:** not adopted. It improves some warm modes but has 1.525857× paired cold median, adds about 3.2 MiB host maxRSS, and does not improve repeated-target lookup; no real target mix justifies the tradeoff.
- **Phase 4 static-BSS storage:** inconclusive and not adopted. Same-size static storage has small variable gains, a repeated-target regression, and unknown Android loader cost after moving 3,145,760 bytes into host ELF NOBITS.
- **Phase 4 alternative hash constants:** no candidate promoted. Eight constants across four miss models produced small workload-dependent tradeoffs rather than a robust improvement; timing one synthetic winner would overfit the fixture.
- **Phase 4 interleaved index8/packed12/bucket2/bucket4:** rejected after standard plus shuffled-locality screening. Index8 reached 1.808098× at 16,384-target lookup and was slower in 12/12 pairs; packed12 did not improve standard hits and regressed several localized cases; buckets added indexing costs and retained repeat/locality regressions (repeat and 16,384-target lookup each slower in 11/12 pairs for both bucket sizes). The layout search stops rather than overfitting more variants.
- **Phase 4 TSO/alignment relaxation:** not adopted. All 192 generated files and one AArch64-musl partition provide static structure only; acquire/release/DMB counts are not dynamic costs and cannot justify weakening guest-memory ordering.
- **Phase 4 Python-launched cold RSS:** rejected as invalid memory evidence because children inherited the Python parent's 16,204-KiB high-water floor. Valid reported cold/RSS comparisons use direct-shell launches; raw invalid logs remain preserved.
- **Phase 4 instruction-count or musl-to-device conversion:** rejected. The production/measurement assembly match is structural only; it does not establish Android/Bionic equivalence, cycles, FPS, pacing, or device memory.
- **Phase 5 rowtile32:** rejected after weaker/inconsistent controlled timing than direct32; exact-output success alone was not enough for adoption.
- **Phase 5 noinline direct32 layouts:** rejected. Early/late helper placement did not improve the overall trade; late noinline regressed DXT1-32 by about 2.9% and was slower for DXT3 than the selected inline form.
- **Phase 5 lazy per-pixel alpha:** rejected despite full normal/ASan+UBSan output equivalence. DXT3/DXT5 BGRA were slower than precomputed direct32 alpha; incidental unchanged-path layout improvements were not treated as algorithmic wins.
- **Phase 5 direct packed16 decoder integrations:** rejected in all four forms. They were output-correct, and packed16 was often faster, but repeated screening A/Bs regressed the selected BGRA path by roughly 38–80%; no long cohort was wasted on those integrations. The separate palette-alpha simplification achieved packed16 gains without that material BGRA cost and is not part of this rejection.
- **Phase 6 naive bounded notification:** rejected by the exact-header model. Waking only the first auto-event/semaphore waiter can strand an eligible single-object waiter behind a multi-object waiter.
- **Phase 6 all=true-only guard:** rejected by the same model. A multi-any waiter can be notified through another object and complete without consuming this signal, so guarding only compound-all waits is insufficient.
- **Phase 6 timeout-leak patch:** not warranted. Exact `WaitKernel` inspection shows both finite and infinite paths remove registered waiters before returning; the preliminary suspicion was disproved without a source change.
- **Phase 6 multi-object-guarded bounded notification:** rejected after the corrected 480-process A/B/control cohort. It passed modeled progress checks but was slower in 16/16 pairs for every four/eight-worker single-release event/semaphore scenario (about 1.45–2.23× baseline median), with no meaningful batch gain over the structure control. The initial drifting batch fixture and abort are excluded and preserved.
- **Phase 6 counted-event CAS-load optimization:** rejected as out of target scope before timing. The interesting `src/core/event.cpp` read/subtract path is compiled by `src/host/Makefile` into the 32-bit Windows hook host; `src/native/Makefile` does not compile it into Android `libmain.so`, and no native registry references it. A host-only utility optimization would not establish 0.16 phone performance.
- **Phase 6 lazy ordinary-Present TID:** not adopted. The 144-process A/A/candidate cohort showed only ~0.48 ns/call median-total separation from baseline, smaller than normal run variation; detailed mode was neutral. Correctness passed, but the change is unnecessary noise.
- **Phase 6 speculative scheduler/media-policy changes:** fixed affinity, fewer ADPF reports, a different frame-limiter anchor, surface-lock removal, Bink yield/sleep changes, and XAudio2 lock relaxation are not adopted. They either alter semantics or require physical device/media evidence. D3D9 lock overhead is deferred to its dedicated Phase 8 profile rather than rewritten blindly.
- **Phase 7 exact-hit RCF basename deferral:** rejected after 12.96 million exact-output opens across full-path and direct-archive A/A/candidate cohorts. Aggregate medians suggested less than 0.5% improvement, but paired rounds did not separate the candidate from the identical control; full-path candidate direction split 18/18 and the direct A/A paired median was slightly better. Baseline/candidate both passed the 8/8 fallback/priority differential. Production source was restored; no startup or streaming claim.
- **Phase 7 speculative RCF index dedup/pointer rewrite:** not attempted. Exact/basename maps duplicate entry strings, but independent duplicate resolution and process-lifetime pointer stability make a naive rewrite unsafe. Twenty-four fresh baseline processes measured 18,620-KiB whole-process median maxRSS, not index-only or Android pressure; no memory problem or saving is established.

## Phase 8 rejected or unsafe alternatives

- Do not claim the fixed-order HostTable timing cohort as a win: identical x86-64 instructions and a faster A/A control exposed order/noise. The balanced cohort is neutral.
- Do not use the optimized-out anisotropy benchmark (147 ns candidate loop) as evidence. Only the separate-translation-unit cohort is canonical.
- Do not remove or bypass `shot_now` polling to make Present faster; the fixed-config candidate preserves the debug feature and exact capture outputs.
- Do not add bridge-only render/sampler state dedup without Reset, StateBlock Apply, Get/Set, and real call-trace evidence.
- Do not remove Mali pipeline-compiler serialization or replace DXVK based on these bridge microbenchmarks.
- The eager screenshot-config move itself is rejected on materiality after the 0.991820 confirmation (22/36 wins), not because of a correctness failure. Its exact 16-case differential passed, but the once-per-Present benefit is too weak to justify extra global lifecycle state.
- Phase 8 measurement-tool development outputs using short noisy cohorts or different baseline/candidate main objects are not canonical. Only the corrected shared-main, separate-implementation protocol is used for CI; earlier `ci-tool-*` outputs remain preserved.
- Phase 8 HostTable chunk-load relaxation (`ca25c46`) is rejected after its initial structural adoption: two actual native ARM64 cohorts combine to 0.999926 (25/48) with A/A 1.000417, and the absolute median delta is only 0.000585075 ns/lookup. The timed candidate was not optimized away. Final source `9a65eb9b59dc1e755d434ae9204affef547ef5d4` restores the original acquire; correctness/CI evidence and the rejected commit remain preserved.

- Phase 9 rejects removing Android cache-entry flushes, accepting partial/corrupt cache entries, removing the Mali pipeline-compilation mutex, or fabricating pipeline warmup. The patched source already has background writing/warmup and safe queue draining; no performance basis supports weakening those behaviors.
- **Phase 9 metadata-only unchanged-backup skip:** rejected after eight failures in 3,304 concurrent differential checks. Same-size target edits inside one timestamp tick made recorded identities insufficient. The adopted tracker therefore compares complete source/target bytes before every skip; metadata-only behavior remains in preserved failing evidence and must not be restored.
- **Phase 9 direct DXVK SHA-1 padding:** rejected for 0.16 on absolute materiality after correct implementation and valid timing, not hidden as a failure. Exact differential/FIPS/chunk/context tests, 384 high/wrapping-count context comparisons, ASan+UBSan, and patched ARM64 correctness pass. Native ARM64 check `126482355374` gives 12/12 wins and 28–218 ns/hash savings across 20–4,096 bytes, independently verified 873/873; however, the subsequently validated real Prototype cache has 1,014 entries and even applying the largest saving to every entry bounds a full cache-load hash pass at only 0.221288058186 ms. Actual 134–174-byte entries were not separately retimed; this conservative bound does not justify another DXVK patch. The production patch and H2 CI scaffolding are removed; candidate `65fda1a`, failed harness runs `41801355490`/`41802404581`, successful measurement `41802645649`, and raw evidence remain recorded.
- **Phase 9 speculative cache/parser/worker rewrites:** not adopted. DXVK already indexes entries during ingestion, deduplicates modules/pipelines, compiles outside module-map locks, and provides background writer/warmup workers. The v18 header has no entry count for a principled reserve, file size is not an entry-count proxy, and the historical 171-call trace's repeated pipeline pairs do not prove a concurrent same-bytecode registration race or justify changing duplicate registration/Mali serialization.
- **Phase 9 text-only full-pipeline dedup:** rejected without a production patch. Canonicalizing only sequence/module handles yields eight duplicate-like groups/nine extra calls, but the trace omits specialization values, pipeline-cache/output handles, and lifetimes. DXVK's existing mutex-protected fast-pipeline key includes specialization IDs and values. Even the same-module sequences 50/52 are not proven redundant; semantic duplication remains inconclusive.
- **Phase 9 exact/prefix cache dedup:** rejected. The real v18 cache has 1,014 distinct payloads and SHA-1 hashes, so there are no exact duplicates to remove. A source-boundary audit finds 303 groups/311 extra entries that share every non-specialization byte but differ in specialization data; merging them would be incorrect. The 44,750-byte repeated-prefix upper bound is too small and speculative to justify a new cache format or metadata cost.
- **Phase 10 disabled-Present diagnostics gating:** rejected on absolute materiality after correct host/native implementation, not hidden as a failure. Native ARM64 run `41836560344` / Check `126597621495` independently verifies 210 checks over 48 rows and saves 102.642780 ns/Present (24/24), but that is 0.000102643 ms, 0.006159 ms CPU/s at 60 presents/s, and 0.000616% of a 60 Hz interval. Semantics/publication/UBSan pass. Nine checks prove the partial-baseline measured parts identical to restored full production; the unrelated include/FIFO hunk is outside the fixture. Candidate `ed28afe` and external raw/tool evidence remain, while the production patch and CI scaffolding are removed.
- **Phase 10 presentation-policy changes:** rejected from the 1,229-check historical audit. Twenty-seven intervals but only three Present-wall calls exceed 50 ms; window correlation is not causation and wall is not GPU time. No FIFO/image-count/frame-latency/lock change is supported.
- **Phase 10 memory/queue rewrite:** no candidate. Restored source passes all patch/compatibility tests; existing managed-copy release, lifetime locks, timed maintenance, and actual-wait instrumentation have no measured redundant work to remove safely.
- **Phase 10 present-blit/diagnostic shortcuts:** no runtime candidate. Store/layout transitions, uncovered-area clear, gamma descriptor validity, and capability/quality-driven shaders are required; heavy tracing is already tour-only and lightweight timing opt-in. Forty-six structural checks and three negative controls protect the audit, with all seven present shaders compiled successfully in exact CI run `41839771476` step 26. No GPU/FPS claim.
- **Phase 10 frame-limiter/signal bypass:** no candidate. Historical Mali uses direct signaling because present-ID/wait are unsupported; direct limiter/fence operations, bounded refresh heuristic, non-underflowing initial frame ID, and destruction waits remain required. Twenty-five checks and four negative controls pass. No physical pacing or input-latency benefit is claimed.
- **Phase 10 Android-owned GPU fast paths/second presentation-pipeline cache:** no candidate. Twenty-seven ownership/barrier checks and a 2,238-check census find no Android-owned barrier-field modification and no repeated exact present-blit structural pipeline. All 171 trace pipelines are single-sample, so MSAA cost/correctness is unmeasured; do not reduce samples, formats, shadows, or effects from this census.
- **Phase 10 allocator/managed-copy rewrite from historical memory:** no candidate. **551 checks** over 61 windows show early loading growth, late net-stable RSS, and retained late virtual growth, but no DXVK/GPU allocation attribution or long-soak pressure verdict. The exact Mali allocator fixture and 2,560,000-mask independently verified sweep are adopted as regression coverage only; they do not justify changing production selection, chunks, destruction, or lifetime policy.
- **Phase 10 final disposition:** no rejected H1–H8 candidate remains in production. The original Android patch hash is restored, validation CI/APK and fresh regression/reproducibility gates pass, and no FPS/pacing improvement is claimed. Further GPU synchronization or presentation changes require new physical-device workload/timing evidence rather than reopening these rejected structural shortcuts.
- **Phase 11 blind Bink plane shortcuts:** no candidate. Fresh exact profiling shows material registered-path cost, but tight matching signed pitches already use contiguous copies. Negative/padded rows cannot be collapsed in display order, padding is not automatically disposable, and both populated sets remain live under current unlock semantics. Do not drop copies or cache movable guest pointers without new workload evidence.
- **Phase 11 conditional ring index subtraction:** rejected after 240-process balanced measurement and 962,723 independent checks. Exact output does not make it beneficial: candidate/baseline is 1.025–1.131 across five rate/wrap/bin configurations, with a loop-carried `cmov` chain. The separate contiguous-span candidate is faster but below the 0.25 ms CPU/s absolute threshold on x86-64; its native ARM64 disposition is pending, so this entry does not claim a final span rejection.
