# Technique matrix

**Phase 2 audit checkpoint; no technique is adopted yet.** `Useful candidate` means worth a controlled ProtoDroid experiment after profiling, not an expected FPS promise. `Already present` is not a 0.16 improvement. `Rejected at audit` means the proposed import is incompatible, unsafe, misleading, or duplicates existing behavior; it is not a claim that a controlled experiment was run.

| 1 | Bound compiler/worker contention; measure before tuning (GoW III, ISS, Bloodborne) | Bounded async queues; GoW III Android uses two compiler workers and zero speculative prep workers; Bloodborne records per-thread wait/CPU costs | Could reduce CPU contention and pacing spikes. Confidence in the principle is moderate; no ProtoDroid gain is measured | More workers can oversubscribe phones; Mali pipeline calls are already serialized for driver safety | Existing DXVK pipeline wait/driver timing, thread CPU, cold/warm cache runs, frame-time distribution, thermals | **Useful candidate for Phase 3/8 measurement; no worker-count change yet** |

## Ranking for the next phase

1. **Measure the existing pipeline compiler and serialization behavior** using the instrumentation already in 0.15; do not add workers speculatively.
2. **Profile guest/render/native threads and real waits** before considering spin durations, affinity, or another queue.
3. **Profile uploads, readbacks, allocation, and cache I/O** before staging retention, page-watch, or cache-cadence changes.
4. Keep D3D9/DXVK/Vulkan changes narrow and capability driven. No renderer, FEX, strict-AOT, unified-memory, or upscaling migration is justified by this audit.

All physical-device FPS, visual correctness, shader latency, pacing, and thermal outcomes remain open. The numbers quoted in `repository-ledger.md` belong to their source projects and contexts; none is a ProtoDroid measurement.
